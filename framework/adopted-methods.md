# Adopted methods

Forge takes methods from other MIT-licensed agent frameworks and adapts them to its own governance. An adoption is
one of two kinds:
- **Copied:** text, a table's structure or a script is taken in substantial part. It is pinned to an upstream
  version, attributed in the owner and in the root `NOTICE`, and diffed against upstream.
- **Idea only:** Forge writes its own text from the idea. It gets a row and a source line for provenance; it is not
  pinned or diffed, and it needs no `NOTICE` block of its own.

A common working practice that Forge states in its own words, with no text, structure or distinctive method taken from
a project, is not an adoption and gets no row.

This register lists
every adopted method that is present in a Forge owner. It is the attribution index and the upstream-tracking list. The
method itself lives only in its Forge owner; the register points there and does not restate it. A method decided but
not yet in an owner gets its row in the change that puts it there.

## When to read and update it

- **Adopting a method:** add its row in the same change that puts it into the owner, and a one-line source in the owner
  (project, license, copyright holder, this register by name); the departures are recorded here only. For a copied
  method, record the pinned version and add the project's notice to the root `NOTICE` if it is not there yet. For an idea-only method, write "idea only" in "Taken" and "not
  tracked" in "Upstream checked".
- **Changing an adopted section:** update "Changed and why" when the section departs further from the source. A
  copied section rewritten until no substantial part of the source text remains becomes idea only: update its row.
- **Upstream check** (copied methods only): diff the pinned file against the current upstream release. Pull in a correction only when it
  fixes a failure the Forge owner can also show. Then update the pinned version and the check date. A row without a
  pinned version has no baseline yet: pin it at its next check by diffing the owner against the current upstream file.
- **Retiring:** remove the row with the owner section. Remove a project's `NOTICE` block only when no row of that
  project remains.

Upstream file paths carry the project's name as a prefix (`superpowers/skills/…`), so they are never read as Forge
paths. Upstream project names identify sources only. Owners describe a method in Forge's own terms and name its source
plainly, BMAD-METHOD included. An earlier rule kept BMAD's marks out of owners; the maintainer lifted it, because naming
a project as a source is accurate reference, not use of its marks as a name for a Forge part (see the trademark notice
in `NOTICE`). "—" means not recorded at adoption.
