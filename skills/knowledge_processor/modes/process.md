# Mode: process

Apply the canonical lifecycle in `../SKILL.md`. Trigger on useful facts, decisions,
corrections and changed state during authorized continuous maintenance, agent
returns, structural changes or selected domain closeout. No engine is needed.

## EXTRACT

Identify useful discrete claims, including failures, limitations and open work.
Separate source statement, observation, proposal and marked inference. Apply the
future-use test; ordinary formatting need not create knowledge. Person references
alone do not establish relationships or justify new entities. Route private person
facts through user-signal, keeping project activity at its own owner.

## IMPACT CHAIN: LOCATE → ASSESS → ACT

Use the owner's navigation and coherent baseline. Classify semantic delta, then
inspect its navigation and known dependents. Expand only for the canonical lifecycle's
ownership/conflict/contract triggers. Read surrounding meaning, not every file
matching a keyword. Assess contradictions, extensions, implications, enabling effects,
obsolescence and concrete work proportionately; never silently discard an obligation.
Clear corrections need no redundant interview; different scopes may coexist.

Apply authorized changes through protected publication. Record concrete future work
in the existing project task/plan/handoff convention. Software task-status mechanisms
apply only when development is selected; a generic capture does not activate them.
Changes to agreed specs or decisions respect their existing amendment authorization.
Follow actual dependencies until reconciled, then stop; PRESENT without pending work
needs neither rewrite nor repeated traversal.

For structural actions first read repository structure conventions and local
README/navigation as applicable. Enumerate live inventory and references, repair
routes, preserve frozen sources and meaningful content. A structural/method change
also needs the project's consistency check where one is defined. Content-only
updates do not invoke a software workflow.

## SIGNAL CHECK and result

A contradiction can reveal a missing trigger or recurring failure. Record a useful
systemic lesson at its owner; do not manufacture a task for every correction.
Return compact actual evidence: NEW/CHANGED/PRESENT, changed owner and dependent
routes, and any unresolved reconciliation/access limit. Do not create permanent
per-fact or no-op audit logs. Development callers may retain their required audit
proof in their own work unit; this mode does not impose it on every daily answer.
